# 협업 규칙 (Git/GitHub)

개인 평가는 **본인 계정의 Issue·커밋·PR·리뷰 기록**으로 확인됩니다. 아래 규칙을 지켜 주세요.

## 0. 처음 한 번

```bash
git config user.name  "본인 이름"
git config user.email "GitHub에 등록된 이메일"   # 커밋 작성자가 본인 계정으로 연결되도록
```

GitHub 저장소 설정 → Branches → `main` 보호 규칙: **PR 필수 + 승인 1개 이상**.

## 1. 작업 흐름

1. **Issue 생성**: 템플릿 사용, 담당자(Assignee)와 완료 조건 작성
2. **브랜치 생성**: `main` 에서 분기
   ```bash
   git switch main && git pull
   git switch -c feat/12-roi-histogram    # 종류/이슈번호-설명
   ```
   종류: `feat` 기능, `fix` 버그, `test` 테스트, `docs` 문서, `refactor` 리팩터링
3. **커밋**: 의미 있는 단위로, 무엇을·왜 바꿨는지
   ```
   feat(roi): ROI 히스토그램을 원본/결과 비교로 표시 (#12)

   - 같은 ROI 기준으로 두 히스토그램을 겹쳐 그려 분포 변화를 비교
   - ROI 범위 밖 입력 시 ValidationError 로 안내
   ```
4. **PR 생성**: 템플릿 작성, 본문에 `Closes #12`
5. **리뷰**: 다른 팀원 1명 이상 승인 → 리뷰 반영 커밋 → **Squash 대신 일반 Merge 권장**(개인 커밋 기록 보존)

## 2. 리뷰 짝

| 작성자 | 1차 리뷰어 |
|---|---|
| 팀원1 | 팀원2 |
| 팀원2 | 팀원1 |
| 팀원3 | 팀원4 |
| 팀원4 | 팀원3 |

주 1회 이상은 짝이 아닌 팀원의 PR도 리뷰해 주세요.

## 3. 리뷰할 때 확인할 것

- 화면이 아니라 `repository.py` 에서 권한을 검사하는가?
- 원본 영상을 덮어쓰지 않는가?
- 잘못된 입력에 사유가 안내되는가?
- 테스트가 추가되었고 `pytest -q` 가 통과하는가?
- 비밀키·비밀번호가 커밋되지 않았는가?

리뷰는 "LGTM"만 남기지 말고, 확인한 내용이나 질문을 구체적으로 적어 주세요. (보고서 근거가 됩니다)

## 4. 공동 작업

페어 프로그래밍 등 공동 작업은 커밋에 `Co-authored-by:` 를 추가하고, PR 본문에 각자 수행한 부분을 적습니다.
